# Web Local Settings

## Outcome

- Add a separate Settings page to the existing menu, reachable without a paired
  or connected Mac. Keep frequent overlay visibility controls in the menu and
  preserve the accepted touchpad, keyboard draft and five-button media row.
- Match native `MediaSeekInterval`: 5/10/15/30 seconds, default 10, used in both
  directions with matching visible and accessible labels. Preference changes
  alone never send or repeat a media command.
- Add three-finger drag preference, default enabled. Turning it off releases an
  active drag once and blocks its remaining fingers until lift; other gestures
  retain their existing behavior.
- Save only the two non-secret fields in browser storage. Corrupt values use
  native defaults; storage failure leaves changes usable in memory with a
  clear lifetime message. No credentials, drafts or native permissions are stored.
- Settings navigation cancels local input and suppresses remote control keys.
  Transport snapshots, backgrounding and reconnect preserve the chosen page;
  Back restores the previous mode or pairing without clearing partial inputs.

## Validation

- Web tests cover native defaults and all interval choices, strict preference
  validation, reload persistence, malformed/unavailable storage and recovery,
  unrelated-key preservation and disabled-drag release.
- Isolated muted browser checks cover phone/tablet/landscape layouts, sticky
  Back reachability, symmetric seek messages/labels, reload, disabled drag,
  keyboard draft retention, offline settings, pairing/resume retention and
  unavailable storage. Existing media, desktop, session and pinch checks remain
  in the same desktop-free harness.
- Type checking, lint, formatting and journal validation cover the source.
  No native protocol, installed app, helper grant or daily payload is changed.

## Next Steps

- After authorized deployment, accept real Safari navigation, persistence and
  target-app seeking. Physical acceptance remains deferred by the user.
- Expand keyboard keys and atomic shortcuts in a separate protocol/native
  slice. Inspection confirms both clients currently share only eight RemoteKey
  values; do not send unsupported or held modifier keys from the Web client.
