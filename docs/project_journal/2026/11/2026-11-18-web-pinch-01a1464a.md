# Web Touchpad Pinch Magnification

## Goal

Continue Web/native parity while physical acceptance of the deployed session
controls remains deferred. Add touchscreen pinch without changing the accepted
layout, single-finger pointer path, scrolling, right tap or three-finger drag.

## Decisions

- Use the existing native cumulative phased magnify protocol and Mac executor.
  Require advertised support and Accessibility; keep older-companion scrolling.
- Classify both contacts within the existing animation-frame input flush. Lock
  each sequence to scroll or magnify using the native thresholds, with no extra
  frame added to input transmission. Begin/terminal frames are ordering barriers;
  intermediate cumulative changes coalesce rather than fill the request queue.
- Renew a stationary gesture lease without advancing queued sample timestamps.
  Cancel on capability loss, finger-count changes, mode/page lifecycle changes
  and disconnect. Never replay a gesture after reconnect.
- Expand the authenticated Web gateway only to magnify frames. Keep swipe kinds,
  malformed payloads, arbitrary keys and shell actions excluded.
- Leave the deployed Mac app, helper authorization, iOS build and daily-renewal
  payload unchanged while this source slice is developed and reviewed.

## Validation

- Web regression tests cover cumulative ordering/coalescing, per-contact pan
  batching, final lifted positions, one-frame sampling, keyboard barriers,
  begin rejection, capability loss, cancellation and stationary lease renewal.
- Gateway package and real TLS/WSS fixture checks cover fixed magnify transport
  and rejection of other gesture kinds and malformed payloads. The fixture
  never posts Mac events or plays audio.
- Isolated muted browser checks exercise touchscreen pointer events and preserve
  the accepted overlays, keyboard draft and existing control groups.

## Next Steps

- After authorized deployment, verify physical iPhone/iPad Safari scroll/pinch
  discrimination, cancellation and touch feel on real target Mac apps.
- Continue richer Web keyboard and settings in separate slices; keep desktop
  Ctrl-wheel behavior and native BLE outside this touchscreen-pinch slice.
