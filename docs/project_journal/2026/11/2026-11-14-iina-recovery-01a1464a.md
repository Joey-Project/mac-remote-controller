# IINA Configuration Recovery and Reliable Volume Results

## Findings

- The installed Sofa Remote plugin was enabled and matched the bundled code, but
  its saved token differed from the running bridge. A read-only nonexistent-route
  probe returned 401 with the saved preference and 404 with the bridge credential.
  No production command queue was polled and no credential was logged.
- IINA 1.5.1 caches the plugin preference dictionary. Reading preferences every
  polling cycle therefore cannot observe a companion-side configuration update.
- Real IINA testing also reproduced a separate volume-result defect: the
  `core.audio` proxy applies a setter but returns a falsy result. Strict-mode
  assignment throws afterward, producing a failure result for an applied change.

## Changes

- Setup writes a private, atomic `@data/bridge.json` alongside the legacy
  preferences. Restoring the companion bridge refreshes an existing IINA setup
  without creating a new opt-in, installing a plugin or enabling it.
- The plugin refreshes only its cached bridge port/token on startup, while
  waiting for configuration, or after a failed request. Healthy polls add no
  file reads. Reads are limited to 4 KiB and use IINA's existing private-data
  API without additional permissions. Manual settings remain supported.
- Volume writes use the supported mpv property API, retaining the accepted gain
  range, percentage conversion and positive-volume unmute policy. Zero-volume
  changes do not clear mute. Playback, seek and playlist actions are unchanged.
- Polling remains serial at 250 ms, with at most eight commands per batch and
  no replay of applied commands. Touchpad processing and all iOS UI are unchanged.

## Validation

- Two configuration regressions failed against the original plugin and passed
  after recovery support. A strict-proxy regression then reproduced false
  volume failures before the mpv setter fix. All 20 plugin tests now pass;
  strict TypeScript checking and Oxlint pass.
- All 343 AppleCore/MacSupport tests pass, including existing opt-in preservation,
  credential-file permissions, restart synchronization and linked-data rejection.
- The isolated Mac app and its incremental rebuild pass with local validation
  signing and strict signature verification. Its preview registration is removed
  from LaunchServices; the fixed-path production app is unchanged.
- Real IINA 1.5.1 and the real MacSupport bridge passed seven isolated checks:
  cached-preference setup, playback/seek/volume, next/previous M3U navigation,
  bridge outage, credential/port replacement, restart with stale preferences,
  and idle-target removal. The final run used the uninstrumented plugin.
  All seven checks also pass using the exact plugin from the built Mac package.
- Tests used a verified private application home and generated silent videos;
  production plugin preferences and bridge configuration remained byte-identical.
  System audio stayed muted and all owned native processes exited.
- Earlier harness attempts stopped at media-load/capability prerequisites,
  assumed a fixed pause state after seek, or appended outside IINA's playlist
  cache. These are retained separately from the final passing run. The actual
  strict-proxy volume failure remains a product regression, not a harness issue.

## Remaining Acceptance

- Complete the signed companion/plugin deployment through the normal fixed-path
  workflow, preserving the unlock helper's exact-code binding. Physical phone
  control and long-duration stability remain separate from isolated acceptance.
- The observed credential mismatch is established; it does not prove that every
  historical intermittent disconnect had the same cause.
