# CI toolchains and template cleanup

## Summary

Establish repository and language checks before native feature development.
Include minimal buildable app scaffolds so compiler, lint, and test jobs validate
real source.

## Current State

- CI checks formatting, Markdown, and all GitHub Actions workflows.
- Tool versions and the pnpm lockfile make dependency installation repeatable.
- Android CI explicitly initializes the pinned SDK command-line tools before
  installing platform/build-tools components; it does not depend on runner PATH.
- Gradle has a 2 GiB heap and at most two workers to keep Android dex merging
  within the runner's memory budget.
- The one-time CI generator, its dedicated tests, and template README are replaced
  by concrete repository tooling and project documentation.
- Existing Codex review workflows, CODEOWNERS, and the Disabled ruleset import
  template remain in place.
- Separate macOS, universal iPhone/iPad, Android, and Chrome extension directories
  own their build-output ignore rules.
- Swift formatter, linter, and editor settings live in each Apple module;
  shared Apple check/bootstrap scripts live in `tooling/swift/`.
- No generated build products or user settings are tracked. Local ignore rules
  also cover archive/test results, installable packages, and signing material.
- Prefer the latest compatible stable releases. CI selects Xcode 27.1/Swift 6.4
  and Node.js 26.12.0. The extension uses TypeScript 7.0.2 with Oxlint 1.88.0
  and oxlint-tsgolint 7.0.2004, replacing the TypeScript 6-limited ESLint stack.
  Prettier formatting and standalone strict `tsc` checks remain separate.
- Oxlint explicitly carries the previous JavaScript and type-aware TypeScript
  rule sets, including unhandled Promise and unsafe-value checks. Source and
  script/test scopes preserve their own rules and globals.
- Android selects AGP 9.4.1, Gradle 9.8.1, Kotlin/Compose compiler 2.4.21,
  Compose BOM 2026.09.00, JDK 27, SDK 37.0 and Build Tools 37.0.0. Java bytecode
  still targets 17, and minimum supported OS versions are unchanged.
- pnpm 12 explicitly permits only esbuild's required dependency build script.
- Swift formatting/lint, Apple and shared-package builds, typed TypeScript
  lint/type checking/tests/build, and Kotlin formatting/lint/Android builds extend
  the repository baseline. Native unit tests follow actual behavior rather than
  empty scaffold test tasks or constant-only assertions.
- The native implementation handoff is recorded separately.

## Next Steps

- Continue native application development through the linked workstream after
  establishing this baseline.
